# 用户端「注销账户」功能文档

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 用户端注销账户（Account Cancellation，含可配置冷静期） |
| 文档版本 | v1.4 |
| 适用端 | 用户端（`php/user/`）+ 管理后台（`php/Adminq/`）+ 定时任务 |
| 涉及后端 | `php/user/ajax.php`、`php/user/*.php`、`php/Adminq/cancel_config.php`、`php/Adminq/Ajax.php`、`php/cron_account_cancel.php` |
| 数据影响 | 冷静期结束（或关闭冷静期时立即）永久删除账号及其个人数据（不可恢复） |
| 状态 | 待开发 |

---

## 1. 背景与目标

### 1.1 背景
- 当前仅**管理后台**可删除用户（`Adminq/ulist.php` → `Adminq/Ajax.php` 的 `setUser&type=del`），已实现「先删子表、后删用户」的级联清理。
- 用户端无任何"注销账号"入口，用户无法自主删除账号与个人数据。

### 1.2 目标
1. 用户端提供**自助注销**：**必须先阅读并同意《用户注销服务协议》**，方可进入注销流程。
2. **冷静期可后台配置**（开关 + 天数，默认开 / 10 天）；冷静期内**重新登录自动撤销**。
3. **邮件通知可后台配置**（提交注销通知、注销成功通知分别开关）。
4. **身份核验方式可后台配置**（密码/邮件验证码/人机验证组合），并支持**注销总开关**。
5. 冷静期内**屏蔽各类推送**（改造推送 cron）。
6. 后台用户列表标注「**注销中**」。
7. 交互与现有用户端统一，适配移动端；具备审计留痕。

### 1.3 非目标
- 不涉及管理员账号（`nteam_admin`）。
- 不提供"账号冻结/停用"。
- 不提供数据导出。

---

## 2. 名词定义

| 名词 | 定义 |
| --- | --- |
| 用户注销服务协议 | 用户注销前必须完整阅读并同意的协议，作为注销与数据处理的合规依据（后台以 **Markdown** 编辑，用户端按 Markdown 渲染） |
| 注销申请 | 用户同意协议并提交注销请求，账号进入冷静期（若开启） |
| 冷静期 | 可配置时长（默认 **10 天**）；期间账号数据完整保留 |
| 自动撤销 | 冷静期内用户**重新登录**即自动取消注销申请 |
| 正式注销 | 冷静期结束（或未启用冷静期时立即）执行永久删除 |
| 级联删除 | 删除 `nteam_users` 的同时删除以其 `user_id` 关联的业务数据 |
| 教务账号保留 | **正式注销时不删除 `nteam_academic_accounts` 记录**（内部规则，见 §8.5） |

## 3. 功能范围

### 3.1 包含

**用户端**
- 注销入口（用户中心首页卡片 + 侧边栏 `Account` 分组）。
- **《用户注销服务协议》**：进入流程前必须阅读并勾选同意。
- 注销申请页：风险告知、数据清单、身份核验、二次确认（表单随后台验证方式动态渲染）。
- 冷静期：申请后退出登录；冷静期内**重新登录自动撤销**。
- 接口：`send_cancel_code`、`cancel_account`、`cancellation_status`。

**管理后台（注销管理配置）**
- 注销总开关、验证方式、**冷静期开关与天数**、**邮件通知开关**（提交/成功）、**协议全文编辑**。
- **用户列表标注「注销中」**。

**定时任务**
- `cron_account_cancel.php` 到期正式删除；**推送类 cron 屏蔽冷静期用户**。

**数据与审计**
- `nteam_users` 冷静期字段、`nteam_account_deletions` 审计表（含协议同意留痕）。

### 3.2 不包含
- 冷静期结束后的账号恢复（不可逆）。
- 管理员侧注销审批（自助流程）。

## 4. 交互流程

### 4.1 入口

1. **用户中心首页** `user/index.php` 的 Account 卡片区新增「注销账户」入口（危险色）。
2. **侧边栏** `user/head.php` 的 `Account` 分组新增「注销账户」菜单项。
3. 直达地址：`user/cancel_account.php`。
4. 未登录访问 → 重定向 `login.php`。

> **不添加**顶部用户下拉菜单（`page-header-user-dropdown`）入口。
>
> 入口**始终展示**（不受注销总开关影响）；当后台关闭注销功能时，进入注销页会提示"管理员未开启账号注销功能"，相关接口亦拒绝。

### 4.2 流程总览

```
[步骤0 阅读并同意《用户注销服务协议》]   ← 未同意不得进入后续步骤
        ↓
[步骤1 风险告知 + 数据清单 + 勾选"已知晓"]
        ↓
[步骤2 身份核验（按后台验证方式）]
        ↓
[步骤3 最终确认（输入确认短语）]
        ↓
   提交注销申请 →（开启冷静期）进入冷静期并退出登录
                →（关闭冷静期）立即执行正式注销并退出登录
```

### 4.3 步骤 0 —— 用户注销服务协议（强制）

- 进入注销流程**第一步**即展示《用户注销服务协议》全文（后台 `Cancel_Agreement` 配置，可在弹层/整页中阅读）。
- 必须勾选「**我已完整阅读并同意《用户注销服务协议》**」后，才可进入步骤 1。
- 未同意：无法进入后续表单，也无法提交（前端拦截 + 后端校验 `agree=1`）。
- 同意记录写入审计表：`agreement_agreed=1`、`agreement_time`、`agreement_ip`。

### 4.4 步骤 1 —— 风险告知 + 数据清单

- 文案（随冷静期开关变化）：
  - 开启冷静期：「提交后进入 **N 天冷静期**，到期后账号及以下数据将被**永久删除且无法恢复**」；
  - 关闭冷静期：「提交后账号及以下数据将被**立即永久删除且无法恢复**」。
- 动态列出该账号数据（宿舍绑定 N 个、教务账号绑定、第三方绑定 N 个、订阅/推送设置 N 条等）。
- 勾选「我已阅读并知晓」。

### 4.5 步骤 2 —— 身份核验

按后台验证方式渲染（见 §5）：
- 需要密码 → 「登录密码」输入框；
- 需要邮件验证码 → 「邮箱验证码」输入框 + 「发送验证码」按钮（60s 倒计时）；
- 始终需要人机验证 → 腾讯滑块，异常时降级图形验证码。

### 4.6 步骤 3 —— 最终确认

- 手动输入确认短语「我已确认注销后用户数据无法找回并确认注销」（提示文字**禁止复制**、输入框**禁止粘贴**，确保用户手动输入）；危险色主按钮「提交注销申请」。

### 4.7 提交后

- **开启冷静期**：写入 `is_cancelling=1`、`cancel_expire_time = NOW() + N 天`；按开关发送「申请已提交」邮件（含"期间登录可撤销"）；**销毁会话并跳转登录页**，提示「申请已提交，将于 YYYY-MM-DD 正式注销；期间登录即可撤销」。
- **关闭冷静期**：进入流程后**立即执行正式注销**（调用与 cron 相同的注销逻辑），按开关发送「账号已注销」邮件，销毁会话并跳转登录页，提示「账号已注销」。

### 4.8 冷静期内重新登录 = 自动撤销

- 用户（密码或第三方）**成功登录**时检测 `is_cancelling=1`：
  - 若 `cancel_expire_time > NOW()`：**自动撤销**（`is_cancelling=0`、清空字段、审计置 `cancelled` + `revoke_time`），登录后一次性提示「您的注销申请已自动撤销，账号已恢复正常」。
  - 若 `cancel_expire_time <= NOW()`：**不撤销**，按到期处理。
- **不设**独立冷静期状态页与手动撤销接口。

### 4.9 到期处理（定时任务）

- 定时任务扫描 `is_cancelling=1 AND cancel_expire_time <= NOW()` 执行正式注销（见 §8）。

## 5. 身份核验方式（后台可配置）

### 5.1 三种验证方式

| 模式值 | 名称 | 校验项 |
| --- | --- | --- |
| `password` | 密码 + 人机验证 | 登录密码 + 滑块/图形验证（默认） |
| `email` | 邮件验证码 + 人机验证 | 邮件验证码 + 滑块/图形验证 |
| `password_email` | 密码 + 人机验证 + 邮件验证码 | 登录密码 + 滑块/图形验证 + 邮件验证码 |

### 5.2 邮件验证码机制

- **发送接口**：`act=send_cancel_code`（需登录、`Cancel_Enable=1`、模式含 `email`）。
- 发送至注册邮箱；存于 `$_SESSION['cancel_code']` / `cancel_code_time` / `cancel_code_email`。
- 规则：6 位数字、**10 分钟有效**、**60s 发送冷却**、**一次性**；发送失败不写入。

### 5.3 安全策略汇总

| 措施 | 说明 | 必备 |
| --- | --- | --- |
| 注销总开关 | `Cancel_Enable` | 是 |
| **协议同意** | 必须同意《用户注销服务协议》 | 是 |
| 登录态校验 | 校验 `$_SESSION['userId']` | 是 |
| 密码校验 | 模式含 password 时 | 条件 |
| 邮件验证码校验 | 模式含 email 时 | 条件 |
| 人机验证 | 三种模式均需 | 是 |
| 确认短语 | 手动输入「我已确认注销后用户数据无法找回并确认注销」（不可复制、不可粘贴） | 是 |
| 冷静期 | 可配置开关/天数；期间登录即撤销 | 是 |
| 频率限制 | 申请/发码限次 | 建议 |
| 审计留痕 | 含协议同意记录 | 是 |

## 6. 前端页面设计

### 6.1 `user/cancel_account.php`

- 复用 `user/head.php` / `foot.php`，风格与 `edit_pwd.php` 一致。
- **分步表单 + 步骤指示器**：顶部为横向步骤条（编号圆点 + 标签 + 连接线；已完成步骤显示蓝色对勾，当前步骤高亮，未开始为灰色），下方每次只展示当前步骤内容，通过「上一步 / 下一步」切换，最后一步为「提交注销申请」。
- 四大步骤：
  1. **阅读协议**：展示《用户注销服务协议》全文（**按 Markdown 渲染**）+ 同意勾选（未同意不可进入下一步）。
  2. **风险告知**：`alert alert-danger` + 数据清单 + 勾选。
  3. **身份核验**：密码框 / 邮件验证码框 + 发码按钮 / 人机验证区（按后台模式渲染）。
  4. **确认提交**：手动输入确认短语「我已确认注销后用户数据无法找回并确认注销」（提示文字不可复制、输入框不可粘贴） + 「提交注销申请」（危险色）。
- 冷静期文案随开关动态展示。
- 移动端适配：步骤条圆点与标签在小屏缩小（媒体查询 ≤575.98px），内容区单列自适应，按钮保持可点区域；切换步骤自动回滚到顶部。
- **功能关闭时**：提示「管理员未开启注销功能」，不渲染表单。
- 协议全文以页内滚动区展示（`max-height` + `overflow-y:auto`）。

### 6.2 交互细节
- 未同意协议 / 未勾选知晓 → 无法进入下一步。
- 提交按钮置灰 + `layer.msg` 防重复提交。
- 发码按钮 60s 倒计时；密码/验证码错误刷新图形验证码并清空。

## 7. 接口设计

### 7.1 `act=send_cancel_code`（发送邮件验证码）
- `POST user/ajax.php?act=send_cancel_code`；需登录且模式含 email。

| code | msg |
| --- | --- |
| 0 | 验证码已发送至您的邮箱 |
| -1 | 请先登录 / 注销功能未开启 / 当前验证方式无需邮件验证码 |
| -1 | 请勿频繁发送，请 X 秒后重试 / 验证码发送失败，请稍后重试 |

### 7.2 `act=cancel_account`（提交注销申请）
- `POST user/ajax.php?act=cancel_account`；需登录、`Cancel_Enable=1`。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| **agree** | **是** | 必须为 `1`（已同意《用户注销服务协议》） |
| password | 条件 | 模式含 password 时必填 |
| email_code | 条件 | 模式含 email 时必填 |
| confirm_text | 是 | 确认短语，须等于「我已确认注销后用户数据无法找回并确认注销」 |
| tc_ticket / tc_randstr | 否* | 腾讯滑块票据 |
| captcha | 否* | 图形验证码（滑块不可用时） |

> *人机验证：`tc_ticket` 与 `captcha` 二者至少提供一个。

**返回**：`code=0` 时附带 `expire_time`（开启冷静期时）或 `immediate=1`（关闭冷静期立即注销）。

| code | msg |
| --- | --- |
| 0 | 注销申请已提交，账号将在 YYYY-MM-DD 正式注销，期间登录可撤销 / 账号已注销 |
| -1 | 请先登录 / 注销功能未开启 |
| -1 | 请先阅读并同意《用户注销服务协议》 |
| -1 | 密码错误 / 邮箱验证码错误或已失效 / 请先完成安全验证 / 验证码错误 / 确认短语不正确 / 操作过于频繁 |
| -1 | 账号已处于冷静期中 / 注销失败[错误信息] |

### 7.3 `act=cancellation_status`（可选）
- 返回 `is_cancelling`、`cancel_time`、`expire_time`、`remain_days`。

> **无独立撤销接口**：撤销由"冷静期内登录"自动完成。

### 7.4 处理流程（`cancel_account` 伪代码）

```
1. 校验登录态 → $userId
2. 校验 Cancel_Enable=1；读取 Cancel_Verify_Mode / Cancel_Cooling_Enable / Cancel_Cooling_Days
3. 读取用户；不存在 → 清会话返回未登录
4. 若 is_cancelling=1 且未到期 → 返回"账号已处于冷静期中"
5. 频率限制检查
6. agree != 1 → 返回"请先阅读并同意《用户注销服务协议》"
7. 人机验证校验；确认短语校验
8. 按模式校验 password / email_code
9. 若 冷静期开启：
     expire = DATE_ADD(NOW(), INTERVAL {Days} DAY)
     UPDATE nteam_users SET is_cancelling=1, cancel_time=NOW(), cancel_expire_time=expire WHERE id=$userId
     INSERT 审计(status='pending', agreement_agreed=1, agreement_time, agreement_ip, verify_mode, academic_retained=1, expire_time)
     若 Cancel_Mail_Submit=1 → 发送"申请已提交"邮件
     销毁会话
     返回 {code:0, expire_time: expire}
   否则（冷静期关闭）：
     INSERT 审计(status='pending'→'deleted', agreement_*...)
     调用 共享注销函数 deleteUserAccount()（见 §8.2、§12.4）
     若 Cancel_Mail_Deleted=1 → 发送"账号已注销"邮件
     销毁会话
     返回 {code:0, immediate:1}
```

## 8. 数据处理

### 8.1 冷静期内
- **不删除任何数据**，数据完整保留。
- **屏蔽推送**：推送类 cron 排除 `is_cancelling=1`（见 §12.2）。
- 登录即自动撤销（§4.8）。

### 8.2 正式注销（冷静期结束 / 关闭冷静期立即 / 定时任务）
- 删除顺序：**先删子表，最后删 `nteam_users`**；置于事务中。

| 表 | 关联字段 | 处理 |
| --- | --- | --- |
| `nteam_dormitory_bindings` | `user_id` | **保留**（置 `status=0` 停用，不删除记录） |
| `nteam_power_daily_records` | `room_num` | **保留**（用电历史，按房间号存储，其他用户可能查询该宿舍电费历史） |
| `nteam_push_settings` | `user_id` | **保留**（置 `is_enabled=0` 停用，不再推送） |
| `nteam_push_logs` | `user_id` | **保留**（电费推送记录/历史） |
| `nteam_user_oauth` | `user_id` | 删除 |
| **`nteam_academic_accounts`** | `user_id` | **保留（不删除）**——见 §8.5 |
| `nteam_academic_push_settings` | `user_id` | 删除 |
| `nteam_academic_push_logs` | `user_id` | 删除 |
| `nteam_tokens` | `user_id` | 删除 |
| `nteam_subscriptions` | `user_id` | 删除 |
| `nteam_subscription_logs` | `user_id` | 删除 |
| `nteam_grade_push_records` | `user_id` | 删除 |
| `nteam_users` | `id` | 删除 |

> **宿舍/电费数据保留策略**：宿舍绑定采用**软删除**（`status=0`）而非物理删除，电费推送设置置为停用、推送记录保留；用电历史 `nteam_power_daily_records` 本就按 `room_num` 存储、不随用户删除。目的是**不影响其他用户查询该宿舍的电费历史**。注意：`cron_power_push.php` 的推送查询已带 `db.status = 1` 条件，停用后的绑定不会再触发推送。

### 8.3 文件清理
- 删除头像 `php/uploads/avatars/avatar_{id}_*.{ext}`；失败不阻断。

### 8.4 不删除的数据
- `nteam_mail_log`、`nteam_log`、`nteam_academic_accounts`（见 §8.5）。
- **宿舍/电费相关数据（按需保留）**：
  - `nteam_dormitory_bindings`：宿舍记录（置 `status=0` 停用，保留）；
  - `nteam_power_daily_records`：用电历史（按 `room_num`，其他用户可能查询该宿舍电费历史）；
  - `nteam_push_settings`：电费推送设置（置 `is_enabled=0` 停用，保留）；
  - `nteam_push_logs`：电费推送记录（保留）。

### 8.5 ⚠ 教务账号保留（内部规则，用户不可知）

> **产品决策**：正式注销时**保留 `nteam_academic_accounts` 记录**（学号、真实姓名、教务 token 等不删除），仅删除其余个人数据与 `nteam_users` 主记录。

**关键约束（务必遵守）**：
1. **一切面向用户的可见信息**（**含《用户注销服务协议》全文**、页面文案、风险清单、申请/注销邮件、提示弹窗）**必须表述为"全部个人数据已删除"**，**不得以任何形式**暗示或透露教务账号记录被保留。
2. 风险告知清单与协议中，教务账号仍列为「将被删除」。
3. 该规则仅存在于本文档与后端代码中，不体现在任何面向用户的界面/文案。

**技术影响**：保留后 `nteam_academic_accounts.user_id` 指向已不存在的用户，形成孤立记录；`nteam_users.id` 自增，不会误关联。

> **合规提示（重要）**：本功能通过《用户注销服务协议》为用户注销与数据处理提供合规依据。**若拟以该协议作为"保留部分记录"的合法性基础，通常需在协议中作出相应告知——这与 §8.5 第 1 条"不得透露保留"存在张力**。请法务明确处理方式（例如：采用泛化的"平台可依据法律法规或学校管理要求，保留必要的记录"表述，而不点明具体保留项）。**在法务确认前，协议措辞不得暗示教务记录保留。**

### 8.6 邮件通知（后台可配置）
- `Cancel_Mail_Submit = 1` → 提交注销申请时发送通知邮件（含冷静期与撤销说明）。
- `Cancel_Mail_Deleted = 1` → 正式注销成功时发送通知邮件。
- `Cancel_Mail_Revoked = 1` → 冷静期内登录**自动撤销**注销时发送通知邮件，含触发撤销的**登录时间**与**登录 IP**（如「您此前提交的账号注销申请，因您于 {时间} 在 {IP} 登录，已为您自动撤销注销申请，账号已恢复正常」）。
- 为 `0` 时**不发送**对应邮件。
- 统一表述为账号及个人数据已删除（见 §8.5 约束）；发送失败不阻断流程。

### 8.7 审计记录
- 全流程写入 `nteam_account_deletions`，含协议同意记录与 `academic_retained=1`。

### 9.2 新增审计表 `nteam_account_deletions`

```sql
CREATE TABLE IF NOT EXISTS `nteam_account_deletions` (
  `id`                INT NOT NULL AUTO_INCREMENT,
  `user_id`           INT NOT NULL COMMENT '被注销用户ID',
  `username`          VARCHAR(50)  NOT NULL COMMENT '用户名快照',
  `email`             VARCHAR(100) DEFAULT NULL COMMENT '邮箱快照',
  `method`            VARCHAR(20)  NOT NULL DEFAULT 'self' COMMENT '方式：self自助/oauth第三方登录入口',
  `status`            VARCHAR(20)  NOT NULL DEFAULT 'pending' COMMENT '状态：pending冷静期/cancelled已撤销/deleted已删除',
  `verify_mode`       VARCHAR(20)  DEFAULT NULL COMMENT '注销时的验证方式快照',
  `cooling_enabled`   TINYINT(1)   DEFAULT NULL COMMENT '注销时冷静期是否开启',
  `cooling_days`      INT          DEFAULT NULL COMMENT '注销时冷静期天数',
  `agreement_agreed`  TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '是否已同意注销服务协议',
  `agreement_time`    DATETIME     DEFAULT NULL COMMENT '协议同意时间',
  `agreement_ip`      VARCHAR(50)  DEFAULT NULL COMMENT '协议同意IP',
  `academic_retained` TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '是否保留教务账号记录（内部字段）',
  `request_ip`        VARCHAR(50)  DEFAULT NULL COMMENT '申请IP',
  `cancel_time`       DATETIME     DEFAULT NULL COMMENT '申请时间',
  `expire_time`       DATETIME     DEFAULT NULL COMMENT '冷静期结束时间',
  `revoke_time`       DATETIME     DEFAULT NULL COMMENT '撤销（登录恢复）时间',
  `delete_time`       DATETIME     DEFAULT NULL COMMENT '实际删除时间',
  PRIMARY KEY (`id`),
  KEY `idx_user` (`user_id`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='账号注销审计表';
```

### 9.2.1 注销日志（复用审计表，不新增表）

「注销日志」不新增数据表，直接由 `nteam_account_deletions` 的时间字段派生事件（每行记录拆为多个时间点）：

| 事件 | 时间字段 | IP 字段 |
| --- | --- | --- |
| 提交申请 | `cancel_time` | `request_ip` |
| 冷静期登录撤销 | `revoke_time` | `agreement_ip` |
| 正式注销 | `delete_time` | `agreement_ip` |

> 通过 `UNION ALL` 汇总后按时间倒序分页展示，无需额外的日志表。

### 10.2 保存接口 `act=save_cancel_config`

## 11. 边界与异常处理

| 场景 | 处理 |
| --- | --- |
| 注销总开关关闭 | 入口仍展示；用户端注销页与接口提示"注销功能未开启" |
| **未同意协议** | 前端拦截 + 后端 `agree!=1` 拒绝，提示"请先阅读并同意协议" |
| **冷静期关闭** | 提交后立即注销，返回 `immediate=1` |
| **冷静期天数为空/非法** | 使用默认 10 天；后台保存时校验范围 |
| 模式含 email 但发送失败 | 提示重试；不写入验证码 |
| 邮件验证码过期/错误 | 返回"验证码错误或已失效" |
| 发码过于频繁 | 60s 冷却，返回剩余秒数 |
| 重复提交申请 | 返回"账号已处于冷静期中" |
| 密码/验证码/确认短语错误 | 返回明确错误，状态不变 |
| 冷静期内重新登录（未到期） | **自动撤销**，账号恢复，审计置 `cancelled`，提示用户 |
| 登录时已到期（未处理） | 不撤销，按到期处理 |
| 定时任务未执行 | 到期后仍可访问，直到下次执行 |
| 任务重复并发 | 以 `is_cancelling=1 AND cancel_expire_time<=NOW()` 条件更新，仅处理一次 |
| 删除部分失败 | 事务回滚，账号保留，下次重试 |
| 邮件/头像删除失败 | 不阻断，记录日志 |
| 邮件通知开关为 0 | 跳过发送，不影响流程 |
